# 팀 작업 경계와 다음 작업

프론트/백엔드 API는 김민솔이 작성 중이므로 여기서는 HTTP 경로·요청 DTO·인증 방식을 확정하지 않습니다. 이 모듈은 문서 목록과 질문/필터를 받아 내부 결과를 반환하는 형태입니다.

## 유하린 — 지금 먼저 할 일

- [ ] K5와 더 뉴 아반떼의 시범 연식·파워트레인을 각각 하나씩 확정.
- [ ] 적용할 법규 시행일과 질문 범위를 확정.
- [ ] 현준·준영과 데이터 규격 v1을 검토하고 합의.
- [ ] 24개 초안 중 시연 질문 우선순위를 선정. 처음에는 법규 2개, 차량 매뉴얼 2개, 근거 부족 1개 정도로 시작.
- [ ] 원문과 추출 청크를 비교해 표·경고·단위 보존 여부 확인.
- [ ] 정답 청크와 기대 답변을 사람 검토해 기준선 평가 실행.
- [ ] 실패를 수집/추출/청킹/필터/검색/답변으로 분류하고 개선 담당자 지정.
- [ ] 민솔 명세가 오면 내부 반환값을 매핑하고 부족한 입력 필드를 협의.

## 변현준 — 데이터

수집 목록 → 공식 PDF 확보 → 적용 범위/이용조건 확인 → registry 등록 → ingest → 추출 품질 확인을 담당합니다. PDF 페이지와 인쇄 페이지를 혼동하지 않습니다. 이후 항목·조항·표 단위 파싱과 청킹을 개선합니다. 산출물은 registry, 원본 해시, chunks.jsonl, ingestion_report와 인덱스 버전입니다.

## 서준영 — LLM·RAG

먼저 실제 필터 검색과 근거 기반 답변을 확인합니다. 평가셋 정답을 하린과 검토한 뒤 검색 결과와 답변을 개선합니다. 의도 분류와 도구 호출은 별도 작업입니다. 현재 코드에 자동 분류/Tool Calling/다중 턴이 구현됐다고 보지 않습니다.

의도 분류 후보:

- 법규 문서 질문 → law RAG
- 차량 사용법/정비 기준 → manual RAG, 차량 규격이 없으면 추가 질문
- 개인 교환 시점 → 차량 규격 + 마지막 정비/주행거리 필요, 문서만으로 판단하지 않음
- 주변/경로 질문 → 지도 도구에 전달, 장소·거리를 LLM이 생성하지 않음
- 메뉴 조작 → 허용된 UI 동작으로 전달
- 실시간 주행 판단 → 지원 범위 밖으로 처리

## 민솔 명세와 나중에 맞출 항목

입력: 질문 텍스트, 대화 식별자/직전 맥락, 선택 차량의 제조사·차종·연식·파워트레인, 필요한 경우 도구가 조회한 개인 정비 정보.

출력: 상태, 화면 답변, 짧은 음성 답변, 출처, 추가 질문 또는 필요한 도구의 종류. 지도 좌표·목적지 변경·DB 저장은 해당 도구의 검증된 결과로 처리합니다. LLM이 만든 코드를 실행하는 구조는 사용하지 않습니다.

초기 통합에서는 음성/STT를 빼고 텍스트 질문으로 RAG를 검증할 수 있습니다. STT 결과가 나중에 같은 질문 입력으로 연결됩니다.
